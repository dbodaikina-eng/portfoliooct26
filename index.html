Works / App fintech 01 / 02

Unlimit CROSS BOARDER BANKING - PAYMENT CASE

Context

Cross-border invoicing worked differently for each country because of local legal requirements and different sets of steps.

The existing flow used long forms on one screen, which made the process difficult for users.

Constraint

The flow had to support different jurisdictions and stay scalable for new countries without making the experience too complex.

Decision

I:

  • split the flow into small, logical steps;
  • adapted questions to each jurisdiction;
  • replaced long forms with shorter screens;
  • tested the full flow with users before launch.

Trade-off

The new flow had more steps and screens, but each step was shorter and easier to understand.

I chose a longer step-by-step flow instead of one large form to reduce cognitive load.

Outcome

  • 95% task completion in pre-launch UX testing, n=15;
  • 44 sec on the first attempt without training;
  • 30 sec on repeat attempts;
  • a scalable flow that can adapt to new jurisdictions.
Works / Payment system 02 / 02

DEMO MODE FOR STARTUP PRESALE

Context

I joined the project to work on the Demo mode and connect different product flows into one system.

At that time:

  • greenlines were created by different designers;
  • some flows and edge cases were missing;
  • the greenlines did not fully match the current product;
  • the future vision was ahead of backend development.

Constraint

The Demo mode had to show something between the current product and the future vision. Some future scenarios were not supported yet, and the product was changing very fast.

At the same time, C-level stakeholders used the Demo mode for pitching, so it had to look clear and polished.

 MY DECISION

  • connected separate greenlines into complete flows;
  • added missing states and scenarios;
  • brought the current UI closer to the future direction;
  • created reusable UX patterns;
  • updated shared library components step by step.

Trade-off

When backend support or product logic was missing, I stopped the flow at a valid happy path instead of designing unsupported states.

I also changed the UI and library gradually, not all at once.

Outcome

  • Product flows became more consistent.
  • More scenarios were covered beyond happy paths.
  • Reusable UX patterns were used across flows.
  • The Demo mode became ready for C-level and stakeholder presentations.
  • The product became easier to extend with new flows and features.
